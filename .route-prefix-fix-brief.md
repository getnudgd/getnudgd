# Fix: role-prefix the Seeker/Insider routes to eliminate a URL collision

## Background

The Phase 0 final review found that `app/(seeker)` and `app/(insider)` — Next.js
route groups, which do NOT affect the URL — both currently plan to serve
`/dashboard`, `/requests`, and `/profile`. Next.js route groups only organize
files; the URL is identical for both, so the first time a real page is added
under both groups, `next build` will fail with a route-collision error
(confirmed against `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route-groups.md`:
"Routes in different groups should not resolve to the same URL path").

The founder has decided: **prefix paths by role**. Seeker routes get a
`/seeker/*` prefix, Insider routes get a `/insider/*` prefix. This means
`app/(seeker)` and `app/(insider)` — which today are non-URL-affecting route
groups — must become literal path segments (`app/seeker`, `app/insider`,
no parentheses) so the prefix actually appears in the URL.

## One consequence you must also handle: the public "Insider landing" page

AGENTS.md §4.5 lists a public marketing page: "Public: landing `/`, `/survey`,
`/login`, `/insider` landing" — a page introducing the Insider role to
visitors, living under the public route group (`app/(public)`), not yet built
in Phase 0. If the authenticated Insider app now owns the whole `/insider/*`
URL space, a public page at the URL `/insider` would collide: it would need to
live inside `app/insider/` alongside `app/insider/layout.tsx` (the
authenticated app-shell layout with the bottom nav), and Next.js layouts wrap
every descendant route — so the public marketing page would incorrectly
inherit the authenticated app shell.

Resolution: rename the public Insider marketing page's future URL to
`/for-insiders` in the spec (no page exists yet to move — Phase 0 never built
it, it's still a Phase 1+ concern per AGENTS.md §4.9's backlog). This keeps
`/insider/*` fully reserved for the authenticated app.
